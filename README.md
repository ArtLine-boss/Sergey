# PrintConfig — конструктор шаблонов полиграфической продукции

Инструмент типографии: справочники (склад материалов, операции, оборудование), конструктор шаблонов изделий с клиентским превью и генерация **технологической карты** с калькуляцией себестоимости. Готовые шаблоны экспортируются в JSON для раздела «Продукция» на сайте.

## Запуск

**Требуется:** Node.js 18+

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:3000`. Все данные (справочники, шаблоны) хранятся в `localStorage` браузера с префиксом `printconfig:v1:` — слой хранения вынесен в [lib/storage.ts](lib/storage.ts) и рассчитан на замену на Supabase.

## Как считается техкарта

1. **Части изделия** (например, «Обложка» и «Блок») задаются в шаблоне. У части: страницы (фиксировано / от клиента / 1 лицо), свой размер (опционально) и ручное переопределение раскладки. Каждый блок опций привязывается к части или ко всему изделию.
2. **Раскладка** считается от оборудования операции печати, выбранной в части: печатная область = лист − 2×непечатные поля; ячейка = размер изделия + 2×вылеты; выбирается лучшая из двух ориентаций.
3. **Листы части:** `лиц = тираж × страницы`, `печатных листов = ⌈лиц / (на листе × стороны)⌉`, плюс листы на приладку (из оборудования) и % отходов операций. Закупочных листов — с учётом раскроя формата материала на печатный формат.
4. **Операции:** количество по единице расчёта (лист / изделие / тираж), ставка производительности подбирается из таблицы оборудования по группе материала → сложности операции → по умолчанию. Время = приладка + количество / ставка; стоимость = время × ₽/маш.-час + расходный материал.
5. Строки сортируются по стадии (допечатная → печать → постпечать → сборка), затем по частям. Техкарта **не влияет** на цену клиента — цены опций задаются вручную; в футере превью показывается себестоимость и маржа.

Опции шаблона участвуют в техкарте только если связаны со складом/операцией (панель «i» у опции → «Связь для техкарты»; при добавлении «Из Склада»/«Из Операций» связь ставится автоматически).

## Интеграция с сайтом («Продукция»)

Вкладка «Шаблоны» → «Скачать JSON» / «Экспортировать все». Формат:

```json
{
  "id": "…",
  "name": "Брошюра A4",
  "description": "",
  "image_url": "",
  "updated_at": "2026-09-07T11:00:00.000Z",
  "config": {
    "sizeLabel": "Размер изделия",
    "sizePresets": ["210 x 297 (A4)", "148 x 210 (A5)"],
    "parts": [{ "id": "part-cover", "name": "Обложка", "pagesMode": "fixed", "pages": 4 }],
    "blocks": [
      {
        "id": "paper-cover", "name": "Бумага обложки", "type": "standard", "partId": "part-cover",
        "visibilityRules": [],
        "items": [{ "id": "pc1", "name": "Меловка 300", "price": 25, "unit": "лист", "children": [], "isHidden": false }]
      }
    ],
    "quantityLabel": "Тираж (шт)",
    "minQuantity": 1, "maxQuantity": 10000, "quantityStep": 50, "quantityPresets": [50, 100, 200]
  }
}
```

В публичный JSON **не попадают**: себестоимость, ссылки на склад/операции (`sourceId`), приостановленные опции, ручные параметры раскладки. Логика клиентского калькулятора на сайте: цена = Σ цен выбранных опций (с учётом `visibilityRules` и `isHidden`) × тираж; блоки типа `binding` требуют счётчик страниц с ограничениями `minPages`/`maxPages`/`pageMultiplicity`.

После переноса хранения в Supabase сайт сможет читать таблицу `templates` напрямую через REST API — формат `config` останется тем же.
